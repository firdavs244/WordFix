3. CLEAN ARCHITECTURE
================================================================

Loyiha Clean Architecture (Robert C. Martin) tamoyiliga asoslangan.
Har bir app (users, words) 4 ta qatlamdan iborat:

```
┌──────────────────────────────────────────────┐
│            PRESENTATION LAYER                │
│  views/ serializers/ urls/ dependencies/     │
│  HTTP so'rovlarni qabul qilish/javob berish  │
├──────────────────────────────────────────────┤
│            APPLICATION LAYER                 │
│  use_cases/                                  │
│  Biznes logika orkestratsiyasi               │
├──────────────────────────────────────────────┤
│              DOMAIN LAYER                    │
│  entities/ repositories(abstract)/           │
│  services/ value_objects/                    │
│  Asosiy biznes qoidalari va modellar         │
├──────────────────────────────────────────────┤
│          INFRASTRUCTURE LAYER                │
│  models/ repositories(concrete)/             │
│  tasks/ adapters/                            │
│  Database, AI, external service integration  │
└──────────────────────────────────────────────┘
```

### Dependency yo'nalishi:
Presentation → Application → Domain ← Infrastructure

- **Domain Layer** hech narsaga bog'liq emas (pure Python dataclasses)
- **Application Layer** faqat Domain ga bog'liq (abstract repos)
- **Infrastructure Layer** Domain ni implement qiladi (concrete repos)
- **Presentation Layer** Application ni chaqiradi (DI orqali)

### Har bir qatlam vazifalari:

#### Domain Layer
- entities.py — @dataclass asosidagi biznes ob'ektlari (UserEntity, WordEntity, etc.)
- repositories.py — Abstract base classes (AbstractUserRepository, AbstractWordRepository)
- services/ — Pure biznes logika (SpacedRepetitionService, XPService, ComboService)
- value_objects.py — Immutable value objects (ProficiencyLevel, EmailAddress)

#### Application Layer
- use_cases/ — Har bir foydalanuvchi harakati uchun alohida class
  - execute() metodi — asosiy mantiq
  - __init__ da dependency injection (repo, service)
  - Django/DRF import lari yo'q (toza Python)

#### Infrastructure Layer
- models/ — Django ORM modellari
- repositories/ — Abstract repo larning concrete implementatsiyasi
- tasks.py — Celery background tasks
- adapters.py — External service adapterlari

#### Presentation Layer
- views/ — DRF APIView klasslar
- serializers/ — Request/Response validation
- urls.py — URL routing
- dependencies.py — Factory funksiyalar (DI container)

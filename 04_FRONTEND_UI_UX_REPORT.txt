4. AUTHENTICATION FLOW
================================================================================

─── Login Page (/login) ───

UI Structure:
  • Card with "Welcome Back" heading + subtext
  • Email input field
  • Password input with toggle visibility (Eye/EyeOff icon button)
  • "Sign In" button (full width, shows Loader2 spinner when submitting)
  • Divider: "or" text between horizontal lines
  • GoogleLoginButton component
  • "Don't have an account? Register" link → /register

Flow:
  1. User fills email + password → submit
  2. Calls useAuthStore.login(email, password)
  3. On success: checks user.has_completed_onboarding
     • If false → navigate to /onboarding
     • If true → navigate to / (dashboard)
  4. On error: toast.error with server message or "Login failed"

─── Register Page (/register) ───

Multi-step form (3 steps) with animated transitions:

Step Indicator:
  • 3 dots connected by lines
  • Active step: bg-primary, past: bg-primary, future: bg-muted
  • Labels below: "Account", "Personal", "Confirm"

Step 0 — Account Details:
  • Email input (required)
  • Username input (required)
  • Google OAuth divider + GoogleLoginButton
  • "Next" button (validates email & username presence)

Step 1 — Password:
  • Password input with visibility toggle
  • Confirm password input
  • Validation: min 8 characters, must contain a digit
  • Inline error messages (red text)
  • Back + Next buttons

Step 2 — Confirmation:
  • Full name input (optional)
  • Review summary showing email, username
  • Back + "Create Account" button (shows spinner when submitting)

Flow:
  1. Register via useAuthStore.register(email, username, password, fullName)
  2. On success → navigate to /onboarding
  3. On error → toast.error with message

AnimatePresence handles step transitions with slide animations.

─── Google Login Button ───

  • Dynamically loads Google Identity Services (GSI) script
  • Renders full-width outline button with Google "G" SVG logo
  • On click: triggers window.google.accounts.id.prompt()
  • Callback sends credential (JWT) to parent via onSuccess
  • Loading state: shows Loader2 spinner + "Connecting..." text
  • If VITE_GOOGLE_CLIENT_ID env var not set → button not rendered
  • 3-second timeout to clear loading state (GSI prompt is non-blocking)

─── Auth Store (useAuthStore) ───

  • Manages: user, isAuthenticated, isLoading
  • Methods: login, register, googleLogin, logout, fetchProfile, initialize
  • JWT tokens stored in localStorage (access_token, refresh_token)
  • initialize() called on app mount — validates existing token by fetching profile

  • Enter: opacity 0→1, y: 12→0, duration: 0.3s, ease: easeOut

  • Applied via PageTransition wrapper component

─── List Stagger (listContainerVariants) ───
  • Container: opacity 0→1
  • Stagger children: 0.05s between each item
  • Item: opacity 0→1, y: 20→0, duration: 0.3s, ease: easeOut
  • Used in: BadgeGrid, word lists, notification lists

─── Card Hover (cardHoverVariants) ───
  • Rest: scale 1, subtle shadow
  • Hover: scale 1.02, elevated shadow (10px 40px)
  • Tap: scale 0.97 (press effect)
  • Duration: 0.2s

─── Flashcard 3D Flip ───
  • Container: perspective 1000px
  • Flip: rotateY 0→180 (spring: stiffness 300, damping 30)
  • Front/Back faces with backfaceVisibility: hidden
  • Triggered on click/tap

─── Combo Indicator Pulse ───
  • Scale pulsing animation when combo active
  • Color tier transitions (yellow → orange → red → purple)

─── XP Popup Float ───
  • Entrance: scale 0→1, opacity 0→1
  • Hold: 1.8 seconds
  • Exit: y displacement upward, opacity fade out

─── Sidebar Width ───
  • Framer Motion animate on width property
  • 72px ↔ 240px, smooth transition
  • Label text AnimatePresence (fade in/out)

─── Progress Bars ───
  • Animated width via Framer Motion
  • Duration varies: 0.4s to 0.8s, easeOut
  • Used in: LevelProgress, XPChart, WeeklyChart, DomainCoverage,

─── Landing Page ───
  • Viewport-triggered reveals (whileInView)

─── Confetti ───

29. API CLIENT ARCHITECTURE
================================================================================

File: src/api/client.ts

Base Configuration:
  • Base URL: VITE_API_URL env var || 'http://localhost:8000/api/v1'
  • Timeout: 30,000ms (30 seconds)
  • Headers: Content-Type: application/json, Accept: application/json

Request Interceptor:
  • Reads access_token from localStorage
  • Attaches Authorization: Bearer {token} header

Response Interceptor — Token Refresh:
  • On 401 response:
    1. If not already retrying, marks request as _retry
    2. If another refresh in progress, queues failed request
    3. Reads refresh_token from localStorage
    4. POST to /auth/token/refresh/ with refresh token
    5. On success: updates access_token in localStorage,
       retries original request, processes queue
    6. On failure: clears both tokens, redirects to /login
  • Failed queue pattern prevents concurrent refresh calls

Response Interceptor — Error Handling:
  • 403 → toast.error("You do not have permission...")
  • 500 → toast.error("An unexpected server error occurred.")
  • No response → toast.error("Network error...")

File: src/api/endpoints.ts

Comprehensive endpoint map (120+ lines):
  AUTH:     register, login, logout, refresh, profile, change-password, google
  ONBOARDING: questions, submit, skip, status
  WORDS:   CRUD, bulk, stats, review, categories, enrich, enrichment-status
  REVIEW:  words, sessions, answer, complete, summary, streak, daily-progress
  TESTS:   generate, history, detail, answer, complete
  GAMES:   speed-round, word-match, word-context, story-builder, listening

  PROGRESS: user-progress, xp-history, badges (user + all)
  NOTIFICATIONS: list, mark-read, unread-count
  IMPORT:  analyze, add, csv-validate, csv-import
  CHAT:    start, history, session-detail, send-message, end
  ANALYTICS: overview, weekly, monthly, difficult-words, word-progress, calendar
